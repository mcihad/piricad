# Command Bus — Rules

> Scope: `/src/command` (CMake target `piricad_command`) — `Bus`, `Registry`, `CommandSpec`/`PIRICAD_COMMAND`, `Value`, `Task<T>`, `Context`, `InputSource`, `Transaction`/`UndoStack`, `Journal`, `Parser`. | Depends on: `piricad_core` only. | Source: piricad.md §2.1–§2.6, §3, §10.4.

## Hard Rules

R1. Every change to `Document` state MUST enter through `Bus::dispatch` (`piricad/command/bus.hpp`) in the fixed order **dispatch → validate → transact → journal**. (§2.1)
R2. GUI, command line, `piricad_script` JSON runner, AI and batch MUST call the *same* `Bus::dispatch` overload. No client-specific entry point, fast path, or trusted flag. (§2.1)
R3. A command invocation MUST be fully expressible as `Value` (`value.hpp`) and MUST round-trip losslessly through the JSONL form `{cmd, args, crs, katman}`; `dispatch(parse(serialize(x)))` MUST produce identical document state as `dispatch(x)`. (§2.2)
R4. Every command MUST be declared exactly once via `PIRICAD_COMMAND` yielding a `CommandSpec` registered in `Registry` (`spec.hpp`, `registry.hpp`) with `.id`, `.names`, `.category`, `.params`, `.undo`, `.flags`, `.summary` all set. `Registry`-generated help and the AI tool catalogue group by `.category` (§2.3).
R5. CLI help, script bindings, AI tool schema and docs MUST be **generated** by walking `Registry` at build or run time. (§2.3)
R6. `.id` MUST be stable, lowercase and namespaced (`core.line`, `core.undo`, `core.layer`, `core.zoom`, `core.erase`, `core.script`, `core.help`). Changing an id is a breaking change and MUST ship a journal migration entry.
R7. `.names` MUST list, in order: Turkish primary, ASCII-folded Turkish variant, English equivalent, abbreviations — e.g. `core.line` = `ÇİZGİ, CIZGI, LINE, Ç, L`. Name matching MUST use the module's explicit Turkish case-folding table (i/I dotted–dotless), never locale-free C functions.
R8. Interactive commands MUST be C++20 coroutines returning `Task<T>` (`task.hpp`) and MUST obtain input via `co_await ctx.point(...)` / `co_await ctx.number(...)`. (§2.4)
R8a. Work a command must not do on the bus thread — a file read (io.md P3) — MUST be a `Job` awaited through `run_job` (`job.hpp`). Where it runs is decided by the SESSION, never by the client: a session the client keeps and resumes later (`Bus::begin_interactive`, `client_driven`) parks in `SessionState::Working` and `Bus::on_job_host` runs the job off-thread; a session driven to completion in one call runs it in place. The command body is one body, and the document and the journal MUST be identical either way (Article 1.2). A host never resumes a session from inside the hook; `Bus::finish` refuses a `Working` session.
R8b. **Long work is a job, and a job is counted** (TODOS F-05). A command whose work grows with the drawing — an import, an export, a topology check, a triangulation, a processing tool — MUST do that work in a `Job` and MUST carry `Flags::LongRunning`, which is what makes a client start it as a session it keeps (`Controller::startsAsSession`) rather than run it straight through with the window frozen; the body is still one body and a script still runs it in place (R8a). The worker is handed ONE control, `JobControl` (`job.hpp`) — the stop and the figure together, `processing::Progress` being the same type by another name — and MUST look at `cancelled()` often enough that a stop lands within 100 ms (io.md R15) and report `at(done, total)`, across its passes with `at(done, total, from, to)`, ending at a thousand. A stopped job returns `ErrorCode::Cancelled` and claims NO result — half a check is not a smaller check — and its command ends with `Session::end_stopped()` (R13c) and a sentence that it stopped; a stop is said as it is and never prefixed "Hata". Enter and the right button finish a command; they do not stop a job (`Controller::finishInteractive`) — Esc and Durdur do.
R9. `Context` (`context.hpp`) MUST resolve every await through the `InputSource` abstraction (`input.hpp`). The `Context` public API MUST NOT expose the input origin (mouse / cli / script / ai) to the command body. (§2.4)
R9a. The input aids — object snap, grid, dik mod, polar and tracking, surface normal, step — MUST act on a point AIMED by a hand and on nothing else. `Value::aimed_point` is that mark; only the canvas makes one (a click through `Controller::supplyAimedPoint`, a grip drag's `nokta`). A STATED point — typed on any command line, carried by an invocation, written in a script, proposed by an agent, replayed from a journal — is exact and `apply_input_aids` passes it untouched: the aperture is pixels, and a screen tolerance MUST NOT decide a written coordinate (TODOS F-03). The mark is not part of `Value` equality and is never serialised; the journal records the resolved point as a statement. This is not a branch on `InputSource` (P10): the value says what it is, whoever supplied it.
R10. Cancellation (ESC, `stop_token`, AI rejection) MUST unwind as `co_return` with the surrounding `Transaction` rolled back, never as a partial commit. (§2.5)
R11. One command = one `UndoStack` entry by default. Deviation is allowed only by declaring `UndoPolicy` in the `CommandSpec`. (§2.5)
R12. A script block, a JSON command array, or an AI suggestion MUST commit as **one merged** `Transaction` = one undo step. (§2.5)
R13. Any validation failure inside a `Transaction` MUST trigger full rollback; zero partial application. (§2.5)
R13a. Inside a batch the rollback is the FAILED COMMAND's edits, not the batch's: `Bus::finish` rolls the shared transaction back to the mark its `Session` took when it began (`Transaction::rollback_to`, `Session::transaction_mark`). The edits before the mark belong to commands that succeeded and are already journalled; taking them back left a journal describing a document that was no longer there, and a Python script that caught the error went on to finish half of itself. Whether the batch then continues is the runner's decision — JSON and an AI plan abort it whole, Python may catch — never the failed command's. (TODOS F-01)
R13b. **A batch that is aborted leaves nothing behind** (TODOS F-05): not in the document, not on the redo stack, not in the journal. The journal line of EVERY command that runs while a batch is open — one that borrowed the batch's transaction and one that ran on its own, like `SÜTUN` — is held by the bus and appended, in order, when the batch closes (`end_batch`), and dropped when it is aborted (`abort_batch`) — a script rolled back at its 251st command must not leave 250 lines a replay would rebuild; the one exception is a command that REPLACED the document (`AÇ`, `YENİ`), written at once, since an opened drawing is not un-opened. After the rollback the bus CUTS THE DOCUMENT BACK to the tail it had when the batch began (`Bus::cut_back`, `Document::truncate_to`, model.md R4a) — rows, layers, styles, columns, blocks and the key counters — gives the active layer back, drops from the selection the keys that name nothing now and puts the project settings back (`AYAR` writes outside the transaction until the document owns the store); a failed or cancelled single command is cut back to its own start the same way (`Session::tail_at_start`). A schema edit that keeps no record — `SÜTUN … sil=evet`, and an amendment, which may rescale every cell — is refused inside a batch, because an aborted one could not give it back. A runner that gives up on a batch calls `abort_batch`, never `end_batch` followed by an undo: that pushed the half-done batch onto the redo stack, where YİNELE brought it back. A JSON script is READ WHOLE before its first command runs; a malformed item refuses the script by line number with the drawing untouched. This amends nothing in R13a: a command that fails inside a batch still takes back only its own edits, and whether the batch then continues is still the runner's decision.
R13c. **A stopped run ends CANCELLED, not completed** (TODOS F-05): a command whose job was stopped and which returns with nothing written calls `Session::end_stopped()` (the host's `Session::cancel()` during a job says the same), so it is neither validated, journalled nor undoable — a stopped processing tool that ended "completed" was journalled as if it had run.
R13d. **Redo re-makes the step in the order it was made** (TODOS F-05): `UndoStack::redo` applies its record oldest first. Newest first is right only when no object is touched twice, and a batch that moved a parcel twice, or moved it and re-valued it so its caption was written twice, came back from YİNELE with the first edit's result.
R13e. **Every step says what it changed** (TODOS F-05): `DispatchResult::changes` (`command/changes.hpp`) is read off the step's own undo record — objects added and erased net of the step, moved or reshaped, re-worded, re-valued, moved to another layer, restyled, re-tied, layers re-set, blocks, sheets, guides and CRS — with the followers the settles moved counted as the changes they are. A batch's result carries the batch's, and its sentence says it; GERİAL and YİNELE say what THEY did from the record they produced; an applied AI plan carries it as `degisiklik`. Computed, never stored, and never a second account of an edit: an edit that bypasses the undo record is already a defect under CLAUDE.md 5.9.
R13g. **One writer while a job runs** (TODOS F-05). From the moment a session parks on a job until it resumes (`Session::park_job`, `resume_job`, and its destructor), the drawing is the job's: the worker reads it as it stood when the command began, and a second writer would be read half-way, or would land between the command's start and its end, where a stop cuts the document back to the start. The bus refuses, for EVERY client alike, a dispatch or `begin_interactive` whose effect carries `DocumentEdit`, a `begin_batch` and a `preview`, with `ErrorCode::Busy` naming the job (`Bus::writable`, `Bus::running_job`); a run nested in a command is that command's own and is not refused. Reading, the view, the selection and the settings stay open. A client told `Busy` sends the same call again when the job is over; nothing it held is burnt by the refusal — a suggestion filed meanwhile waits unpreviewed and is offered to the approval policy and previewed when the job returns (ai.md R33).
R13h. **A long answer counts before it lists** (TODOS F-05). A command whose findings grow with the drawing — TOPOLOJİ's defects — MUST say first how many and of which kinds, then list a bounded few (twenty), then count the rest; EVERY finding goes in its structured answer (`Context::report`) and, where it has a place, on the canvas (`Context::mark`). Four thousand lines on a transcript are the same as none.
R13f. **One preview for every client** (TODOS F-05, `command/preview.hpp`): `Bus::preview(steps)` runs the steps through `dispatch` inside one batch — or, inside an open batch, from a savepoint in it — counts what they changed (`ChangeSummary`) and collects the outlines of the objects they leave, then takes them back whole: rollback, cut back to the tail (rows, keys and the revision, model.md R4a), journal lines dropped, project settings, selection and tracking marks restored, `on_command_finished` not called. A step whose effect the take-back cannot reach is NOT run and is listed with its reason — `FileWrite`, `ExternalWrite`, a `SettingsChange` other than the project's, a `ViewChange` without an edit, `core.open`/`core.new`, and a `ReadOnly` command with a `DocumentEdit` effect (GERİAL, YİNELE, applying a suggestion) — and for an agent, a command without `AiAccessible`. There is no second, simulated implementation of any command: what a preview says is what the command does. Its clients — `ÖNİZLE`, `BETİK … onizle=evet`, the suggestion card (ai.md R33) — say it in the future tense (`ChangeTense::Would`).
R14. Topology checks, mevzuat rules and geometry validity MUST run inside `Bus` between dispatch and transact, never in a client. (§2.6)
R15. Argument arity, type and range MUST be declared as `Param` in the spec and checked by `Bus` **before** the command body runs. (§2.3, §2.6)
R16. `parser.hpp` MUST expose exactly one grammar object, used by both the command line and the script engine. (§3, implementation note)
R17. The parser MUST accept absolute `485320,4310220`, relative `@50,30`, polar `@100<45`, inline expressions `@(100*3),0`, and POINT FUNCTIONS `orta(A,B)` · `ile(P,@dx,dy)` · `dik(A,B,ayak,boy)` · `semt(S,açı,kenar)` · `kes(A,açı1,B,açı2)` · `kes(A,r1,B,r2,sol|sağ|yon=<nokta>)` · `kes(A,B,C,D)` · `ara(A,B,oran|mesafe m)` · `uzanti(A,B,mesafe)` · `xy(P,Q)` · `n(nokta_no)` · `son`, and MUST convert to `Mm` int64 fixed point exactly once, at the parse boundary. (§3, TODOS-CAD P1a)
R17a. A point function MUST resolve to one `Point2` BEFORE dispatch, so no `CommandSpec`, validator, body or journal line ever sees a call. A function's argument list MUST be matched against the declared signatures and MUST be refused when more than one fits: a point argument written as bare coordinates spends two comma-separated fields, so arity alone cannot say which shape was meant, and choosing one in silence is what R19 forbids. Where a function needs the document — `n(1284)` — it MUST reach it through a lookup the CALLER supplies (`ResolveContext::named_point`), never through a global; a caller with no document supplies none and the function refuses by saying so. (§3, TODOS-CAD P1a)
R18. Transparent commands (`Flags` transparent, e.g. `core.zoom`) MUST *suspend* the running coroutine and resume it, never cancel or restart it. (§3)
R19. Every failure MUST be returned as `Result<T>` with `Error{code, message}` and the message MUST name expectation and input — e.g. `"Expected: 2 numbers or an object snap. Got: 'abc'"`. (§3)
R19a. A command that DECLINES — the object is the wrong kind, the input names nothing, the edit cannot be made — MUST say so through `Context::refuse`, which fails the session with the sentence as the error. It MUST NOT `echo` the sentence and return: that reports SUCCESS to every client that is not reading the transcript, and a script, an agent and Python then believe the work was done (TODOS F-01 measured 38 such cells). `echo` is for what a command SAYS about work it did or an answer it gives — a listing, a measurement, an empty search result, "nothing to do" when the requested state already holds. A cancel is neither: Esc settles the session as `Cancelled`, and the bus reports it as such. `scripts/ci-gate-kapsam.sh` fails when the measured support matrix shows a silent refusal.
R20. `Journal` (`journal.hpp`) MUST be append-only JSONL, written after commit, and MUST be replayable to reconstruct document state. Exactly two line kinds exist: `{cmd, args, crs, katman}` for a committed command, and `{kind:"meta", ...}` for a non-command record (script sandbox level and consent — `.claude/script.md` R11/R20; plugin id, hash and user decision — `.claude/plugin-api.md` R10). Replay MUST apply the first kind and ignore the second. (§2.2)
R21. Journal writes MUST be enqueued from the calling thread and performed on a dedicated writer thread. (§10.4)
R22. The dispatch hot path MUST be allocation-free: arguments live in a POD union or a per-thread arena. Budgets: script dispatch ≤ 10 µs, command-line keystroke → screen ≤ 30 ms. (§10.4, §10.1)
R23. `TOPLU_BASLA` / `TOPLU_BITIR` MUST collapse N commands into one validation pass and one undo step. (§10.4)
R24. `piricad_command` MUST compile Qt-free and link only `piricad_core`; see `.claude/core.md` for the core purity rules.
R25. Commands owned by `/src/domain` (ifraz, tevhit, yola terk, DOP) MUST be registered through the same `Registry` and obey R1–R23; their domain semantics live in `.claude/domain.md`.

R26. A command's STRUCTURED answer is `Context::report`, surfaced on `DispatchResult::report`; what it SAID is `DispatchResult::lines`, captured per dispatch. A client that is not a person MUST NOT have to parse Turkish prose to learn a count, and `DispatchResult::message` is empty on success — which is why a read command's answer used to be unreachable to anything but the transcript.
R27. `Param` declares its word list (`choices`) and its numeric range, and the BUS validates both before the body runs (Article 1.3). A body MUST NOT be the only place a keyword list exists: the generated schema needs it as an `enum`, the command line needs it to print, and an agent cannot guess it from a help string. `ToolParam` has always carried both and `to_command_spec` used to drop them.
R28. **What a command takes from the selection is declared on its spec** (`CommandSpec::targets`, `command/targets.hpp`), in the classes a user sees — point, line, area, curve, caption, hatch, dimension, block, leader — never in kind ids: an open polyline and one with arc edges are both a line, a parcel and a parcel with a rounded corner both an area (`target_of`, model.md R9b). The declaration states what the BODY accepts, so the two MUST agree: a command that refuses a caption does not declare captions, and a command whose selection is not what it changes — BUDA's and UZAT's selection is their boundary — declares nothing (`Any`). Every command that declares targets carries a `Selection` parameter (`test_targets.cpp`). It is read by every client alike: the ribbon greys by it (ui.md R54), the reference prints it (`Uygulandığı nesneler`), an agent's tool description says it; and an Araçlar tool's comes from its `Applies` (processing.md). The body still judges each object and refuses, in words, one it does not take. ONE NAMED GAP, removed by TODOS O-3: BİRLEŞTİR declares areas and refuses an area with arc edges, because its union is Clipper2's over vertex rings and would return the arcs as chords; the refusal says so, and the gap closes when the union goes through the kernel (CLAUDE.md 2.11).
R29. **A length is typed with its unit through the one parser, and lands in the unit its parameter is DECLARED in** (TODOS U-02). `12.5 m`, `1250 cm`, `12500mm` and `(2m+50cm)` are read by `ExprParser` (`allow_units`, CLAUDE.md 5.11) — never by a client's own conversion, which is what the shell's `toDouble` was — and are the SAME double: a unit shifts the decimal exponent of the literal, it does not multiply (`evaluate_quantity`). A token written with a unit carries `is_length`; the binder works it out again in the unit `Param::length_exponent()` reads from `Param::unit` (`m` 0, `mm` and `kâğıt mm` -3), and a parameter that declares none REFUSES it by name — `sayi=5m` is an error, not 5. So `Param::measured_in` is not a comment: a length parameter that does not declare its unit cannot be typed with one, and every `Integer` or `Number` length MUST declare it (`test_registry.cpp`). A text parameter keeps the letters it was given (`KATMAN ad=10m`). Units are dimension-checked as quantities (a length plus a bare number, a length times a length, a length to a power are refused with a sentence); the filter grammar never takes them. The journal records the converted NUMBER, so a replay needs no parser to know what was meant (Article 1.4). The typed answer at a number prompt takes the same road (`evaluate_answer`) and adds only the decimal comma, which a prompt can take because it has no coordinate for a comma to be — except at a prompt that is also answered by pointing at a distance (`pick_distance`), where a lone `a,b` stays a point. **A PROMPT'S UNIT IS NOT ITS PARAMETER'S**: `OFSET mesafe=` is an Integer in millimetres and its prompt a Number asked in metres that the body multiplies, so reading the parameter's unit for the prompt would turn `5 m` into five kilometres. `prompt_length_exponent` (`session.hpp`) is the one place that says which unit a prompt asks in — a Number prompt of an Integer length is metres — and the probe of OFSET's prompt (`PIRICAD_ANSWER_PROBE`) holds it.
R32. **A one-shot object snap is a WORD typed at a point prompt, spent by the next aimed point** (`snap_mode_from_word`, `Session::temporary_snap`, `aids_for(…, temporary)`; TODOS U-03). The words are the modes' own ids and labels (`core::snap_mode_id`/`snap_mode_label`, so a mode added there is typeable the day it is), folded the Turkish way (5.6), plus the three-letter English names; only object modes — the grid, polar and tracking need no geometry. It PUTS THE RUNNING OBJECT SNAPS ASIDE for one answer (direction locks, grid and polar stay), borrows a reach for a constructed mode the settings gave none, and does nothing at a prompt that takes no aid (`Prompt::aids`, a pick, a fence). The shell routes it before the registry only where the word is not itself a command (`KES` trims); the preview calls the same `aids_for` as the aids road, so the marker promises the point the click takes (F-03). It is spent by the aimed point and dropped by the next `Session::park`; a STATED coordinate is never moved by it, and the journal holds the point it put, never the word (6.4). Esc takes it back before the tool (`Controller::dynamicRelease`).
R33. **A command that builds a drawing by running a script JOINS the batch it is in, and writes no journal line of its own** (`BETİK`, `ÖRNEKPROJE`; TODOS U-06). `JsonRunner::run_text` opens a batch only when none is open: called inside one, its steps are the open batch's steps — one undo step, and a failure is the CALLING command's failure, so the owner of the batch (an outer script) rolls the whole thing back and says "Betik bütünüyle geri alındı" once. A sample project is `core.new` DISPATCHED (not imitated: it is a journal line, so a replay starts from an empty drawing) followed by the project's script, and the command carries `ReadOnly` as `BETİK` does, so its journal is the commands it ran and a replay cannot build the project twice. The same line from the command line, the GUI and a JSON script leaves one drawing and one journal (`test_samples.cpp`). A failed refusal inside a batch does not warn about a tail it cannot cut: the batch's abort cuts to its own tail, once (`Bus::cut_back`).
R34. **A refusal that names an object says WHY it is not there, in the one place all of them fail through** (`Session::fail` → `completed_missing_object`; TODOS U-06). Some fifty command bodies say `Nesne bulunamadı veya (zaten) silinmiş: N` and none knows the cause; the key allocator does — an id at or past `peek_entity()` was never given (a typo: "verilen son kimlik M", find it with SEÇ/NESNEBİLGİ), one below it is gone (an ifraz, a merge or SİL replaced it: SEÇ finds the new id, GERİAL brings it back). Their words stay first and unchanged; only the bare `…: N` form is completed. A point refused by the parser says what was typed and one that works (`X koordinatı: … yazılan 'a'. Örnek: …`), a sheet that is not there lists the sheets that are.
R35. **A ROW'S VALUE IS READ BY ONE COMPILED ENGINE, and it is asked three questions — two of them answered today, the label is the third and not yet connected** (`piricad/command/expression.hpp`, TODOS G-03). The filter bar ("is it one of these"), the field calculator (`ÖZNİTELİKHESAPLA`: "what is the value for this row") and a label ("which text does it print") speak ONE language — `"alan_m2" > 2000`, `round("alan_m2" * 0.4, 2)`, `"ada" || '/' || lpad("parsel", 3, '0')`, `CASE WHEN … END` — compiled once into a tree (`Expression::compile`) and walked once per row (`evaluate`), so a million rows are a million walks and ONE parse. `evaluate_predicate` (`parser.hpp`) is this engine asked for a yes or a no; the grammar that used to live in `parser.cpp` as `PredicateParser` is gone, not copied. **NULL is not 0 and not ''**: arithmetic and `||` with a NULL are NULL, a comparison with a NULL is false (`!=` included), `IS NULL` asks and `coalesce` answers; a cell that is wholly a number is a Number that REMEMBERS its text, so `0012 || 'x'` is `0012x` (the ada/parsel zeros a surveyor cannot lose). **No function reads the clock, the machine or the locale** — numbers are read and written by digits (`core::parse_decimal`, `format_general`), case folding is `core::turkish_lower`/`turkish_upper` — so a calculation journalled today replays to the same cells anywhere (Article 1.4, 6.4). The function table is ONE table (`Parser::function_table`) carrying name, arity, usage and help; the calculator window lists `expression_functions()` and `expression_pseudo_columns()` and the manual's tables are checked against both by a unit test, so the window, the parser and the page cannot disagree. The `$` words (`$fid`, `$alan`, `$uzunluk`, `$x`, `$y`, `$katman`) are answered by the CALLER's `FieldReader` (the calculator reads the document; the filter reads the table's cells). **The command line's quantity arithmetic (`ExprParser`: units, `^`, coordinates) is the other reader and stays in `parser.cpp`**: it turns typed numbers with units into one double and has no columns; this engine has columns and no units. The calculator computes EVERY row before writing ANY (a refused row writes nothing), converts the value into the column's own type with `core::attr_parse` — the only text-to-cell inverse — and REFUSES a fraction for a whole-number column rather than rounding it; a Length column takes METRES from a number and millimetres from a text, as `ÖZNİTELİK deger=` reads it.
R36. **A FEATURE CLASS IS A DATA PACKAGE, AND THE LAYER ONLY SAYS WHICH ONE IT FOLLOWS** (`piricad/command/feature_classes.hpp`, TODOS G-04). A class — "Bina", "Yol ekseni" — names a geometry (`nokta`, `cizgi`, `alan`), a layer, the fields it carries with their defaults and choices, a look and two size limits. The definitions are `/data/catalogs/cad/kalem-katalogu.json` (or the package `core.kalem.katalog` points at), validated by `kalem-katalogu.schema.json` and REFUSED AT LOAD, class and field named — an unknown type, a default the type cannot read, a default outside the field's own choices, two classes on one layer. What the document stores is `Layer::feature_class` = `<package id>@<version>/<class id>` and nothing else (model.md R48): the rules are read from the package when the drawing is edited, so a corrected definition reaches every drawing that follows it and a drawing opened where the package is missing keeps all its objects and says it cannot check them. **ONE PLACE ENFORCES, FOR EVERY CLIENT** (Article 1.2): `settle_feature_classes`, run by the bus after a command's edits and BEFORE the other settles, for every object CREATED on a class layer or MOVED onto one — it fills each EMPTY field from the class default (a typed value is never overwritten; no default leaves the cell empty, never zero) and REFUSES an object whose geometry is not the class's, rolling the whole command back (Article 1.6). It does not look at objects that were merely reshaped (an edit that opens a face is G-05's topology work) and not at objects that were on a layer before it followed a class (`KALEM` counts them and says they were not checked). **THE CHECKS THAT NEED PAPERWORK ARE ASKED, NOT ENFORCED**: required fields, the minimum area or length and the choice lists are reported by `KALEMDENETİM` (`check_feature_class`), never refused on write — a parcel is drawn before its number is known. `KALEM` builds the layer (colour, width, a fill SYMBOL LAYER for an area, group and description only when the layer is NEW), declares the columns and binds; a field that more than one class of the package carries is the PROJECT's column from the start, one only this class carries is scoped to its layer, and an existing column of another type is refused BEFORE the first change. A column once declared is not undone (the `SÜTUN` rule), so widening a column scoped to another layer is refused inside a batch. `KALEMBAĞLA` previews with `onizle=evet` and a preview writes NOTHING (no layer, no column, no move); objects of the wrong geometry or on a locked layer are SKIPPED AND COUNTED, a mapping (`kaynak:alan`) carries a value only between columns of one type or into a text field, and a wrong mapping refuses the whole command. The package file is read again when its size or time changes (`Bus::feature_classes`), so editing it needs no restart.

R31. **The length and the angle typed beside the cursor are state of the QUESTION, and the point they make is the point of a line a person could have typed** (`DynamicEntry`, `Session::dynamic`, TODOS U-02). The state (active field, what each locks) lives on the `Session` and starts afresh at every `Session::park`; the shell feeds it the command line's text (the line IS the active field's text box) and draws `shown()`. It has NO arithmetic of its own: `compose` writes the figures as `@L<A` — the part the mouse still decides written out exactly, the length in whole millimetres, the angle in whole micro-degrees — and `parse_point` reads it, the one grammar (5.11). So `aimed click + lock`, `Enter on a typed pair` and the same figures in a script are one point (6.4), and a lock is never journalled, only the point. The hold is applied on the aids road (`apply_input_aids` → `Session::dynamic_point`), to a point a hand AIMED only, so a stated coordinate stays exact (F-03); the canvas draws the guide at the same call, so what is shown is what is taken. A bare length (`12.5`, no comma — `12,5` is the point (12; 5)) is "that far along where the hand points" and needs the cursor, which a headless client does not have: it must send the angle too.

R30. **A prompt may take a WORD beside a point, and the word never reaches the record** (`Prompt::words`, `PromptWord`, TODOS U-01 "çizim anında komut seçenekleri"). `K`/`KAPAT`/`CLOSE` at ÇİZGİ's or ÇOKLUÇİZGİ's next-point prompt closes the run. The word is typed as the WHOLE line (`K 1,2` is a coordinate pair), folded as every name is (5.6), and is asked before the registry — a prompt that offers `K` means `K`. It resumes the body with an empty answer exactly as a taken-back point does, and the body tells it from ESC with `Context::chose()` (once, like `took_back`). A word that changes the drawing MUST record the points it implies and nothing else — closing re-records the first point, so `ÇOKLUÇİZGİ a b c d`+`K` and the script `noktalar=[a b c d a]` are one drawing and one journal line (6.4); a replay needs no word because there is none to replay. A word is never a privilege: a client that cannot type a line (script, AI) sends the points. Do not offer `C` in a drawing prompt: folded, it is ÇİZGİ's own `Ç`.

## Absolute Prohibitions

P1. NEVER add a mutation path reachable from the GUI that is not reachable from CLI, script and AI. (§2.1)
P2. NEVER mutate `Document` outside an open `Transaction`.
P3. NEVER maintain a second, hand-synced command list — no menu table, no CLI table, no AI tool JSON file, no docs table that is not generated from `Registry`. (§2.3)
P4. NEVER grant a client a privilege, bypass token, `trusted` flag, or validation-skipping mode.
P5. NEVER flush or `fsync` the `Journal` synchronously on the UI thread. (§10.4)
P6. NEVER commit an undo step that leaves a half-applied cadastral or imar edit. (§2.5)
P7. NEVER check argument arity, type or numeric range inside a command body; those three MUST be `Param` declarations validated by `Bus` (R15).
P8. NEVER hand-roll a state machine, `enum State` member, or callback chain for an interactive command; coroutines only. (§2.4)
P9. NEVER use `std::function`, `std::shared_ptr`, `new`, or any container that allocates in the dispatch hot path. (§10.4)
P10. NEVER let a command body ask, branch on, or log the `InputSource` kind. (§2.4) What decides behaviour instead is the EMPTINESS OF AN ARGUMENT: `POLİGON` asks for its readings when `aci=` was not supplied and does not when it was, which is "was I told" rather than "am I interactive" — the same body serves a script and a hand without knowing which is which. Enforced by `scripts/ci-gate-tek-yol.sh` over `/src/command/src/commands`, `/src/domain/*/src` and `/src/ai/src/commands`; the BUS may read the origin and does, because journalling who asked is the opposite of behaving differently because of who asked.
P11. NEVER add a second parser or grammar for the command line. (§3)
P12. NEVER `#include <Q...>` anywhere in `/src/command`.
P13. NEVER call `std::toupper` / `std::tolower` on command names or Turkish arguments.
P14. NEVER let a client hand raw coordinates to a command body without passing through `Parser` and `Value`; AI-produced coordinates are additionally governed by `.claude/ai.md`.
P15. NEVER silently ignore an unknown or surplus argument — reject with `Error`.
P16. NEVER let a `Task<T>` command capture a raw pointer or reference to `Document` across a `co_await`.

## Definitions of Done

- [ ] New/changed command is declared once with `PIRICAD_COMMAND` and appears in `Registry` with Turkish + English + abbreviations.
- [ ] `Registry`-generated CLI help, script binding and AI schema were regenerated; no file was hand-edited to match.
- [ ] Interactive path is a `Task<T>` coroutine; cancellation test passes with empty undo stack delta.
- [ ] Same command driven from GUI, CLI and JSON produces byte-identical `Document` state and identical `Journal` lines.
- [ ] Journal replay of the new command reproduces the golden document.
- [ ] `Value` round-trip test added; validation-failure test asserts full rollback.
- [ ] Error strings state expectation and received input.
- [ ] `tests/bench` shows dispatch ≤ 10 µs and no allocations on the hot path.

## Enforcement

- `scripts/ci-gate-core-purity.sh` — fails on `#include <Q...>` or any non-`piricad_core` link in `piricad_command` (R24, P12).
- `scripts/ci-gate-command-mutation.sh` — fails on `Document` mutation outside a `Transaction`, on any second command list not generated from `Registry`, and on `std::function`/`shared_ptr` in dispatch (P2, P3, P9).
- `/tests/journal` — journal replay regression suite: replay must reproduce golden documents bit-identically (R3, R20).
- `/tests/unit` — the equality proof test: one command issued from GUI client, CLI string and JSON array must yield identical document state and identical journal lines (R2, R5); plus rollback, cancellation, `TOPLU_BASLA`/`TOPLU_BITIR` merge and error-message-format tests (R10, R13, R19, R23).
- `/tests/bench` — dispatch latency and allocation-count gates; > 10 % regression breaks the build (R22).
