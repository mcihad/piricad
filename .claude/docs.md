# User Documentation — Rules

> Scope: `/docs` and every user-facing surface it describes  |  Depends on: everything  |  Source: kentoscad.md §13 ("Doxygen (API) + MkDocs (kullanıcı) dokümantasyonu, ikisi de CI'da yayınlanıyor"), §2.3, §3, §5.2

## Hard Rules

R1. Every user-facing feature MUST have a page under `/docs` before the change merges. "Shipped but undocumented" is an unfinished change (CLAUDE.md 6.12).
R2. All user documentation MUST be Markdown under `/docs`. No PDF, no wiki, no docstring-only, no README scattered outside `/docs` except the repository root `README.md` and the one-line directory `README.md` files that point into `/docs`.
R3. User documentation MUST be Turkish. The users are Turkish surveying engineers and planners and the Turkish domain language is the product (§5.6, §13). The rulebooks in `.claude/` and `CLAUDE.md` stay English; do not mix the two audiences in one file.
R4. `/docs/README.md` is the manual's index and MUST link every page in `/docs`. An orphan page is a defect.
R5. Every page MUST open with a level-1 heading, then one sentence stating who the page is for and what they will be able to do after reading it.
R6. Every command in the registry MUST have its own page at `docs/komutlar/<son-id-parcasi>.md` — `core.line` → `docs/komutlar/line.md`. Adding a command without its page breaks the build.
R7. A command page MUST contain, in this order: **Ne yapar**, **Adlar** (Turkish, English, abbreviations), **Sözdizimi**, **Parametreler**, **Örnekler**, **Geri alma**, **Betikten kullanım**, **Hatalar**. A missing section breaks the build.
R8. Every command page MUST show the command used all three ways it is reachable — command line, GUI, and JSON script — because they are equal clients and the manual must not imply otherwise (CLAUDE.md 1.2).
R9. `docs/komutlar/referans.md` is GENERATED by `kentos_docgen` from `Registry`. It MUST NOT be edited by hand and MUST be regenerated in the same commit as any registry change (`make reference`).
R10. Every example MUST be runnable exactly as printed. Coordinates use TUREF/TM30 metres, and a script example is a complete, valid file — never an excerpt with an ellipsis.
R10a. Fenced blocks carry a contract the test suite executes:
  * **untagged** ` ``` ` — command lines a user types. Every line that starts with a
    registered command name IS RUN by `tests/unit/test_docs.cpp`.
  * ` ```json ` — a JSON document. It must parse; if it is a command script it is RUN.
  * ` ```text ` — application output, transcript excerpts, alias lists, syntax skeletons.
    Never executed.
  * ` ```bash ` — shell commands. Never executed by the suite.
  * ` ```jsonl ` — journal excerpts, one object per line. Never executed.
  Mislabelling an output block as input breaks the build, which is the point: it is how
  the manual proves its examples are real.
R11. Every error message a user can hit MUST appear in a **Hatalar** section with its cause and its fix, quoted verbatim from the source string.
R12. A regulatory statement MUST cite its regulation, annex and madde with a publication date. An uncited claim about BÖHHBÜY, MPYY, TUCBS or a TKGM procedure is not documentation, it is a liability (§5.5).
R13. A page describing behaviour that does not exist yet MUST say so in its first paragraph, naming the phase and the tracking rulebook. Aspirational documentation written in the present tense is forbidden.
R14. Terminology MUST match `docs/sozluk.md`. A domain term used in a page and absent from the glossary is a defect.
R15. Screenshots and diagrams, when present, MUST be regenerable from the repository — a command line, a script, or a Mermaid block in the page. No hand-placed binary that nobody can reproduce.
R16. Keyboard access MUST be documented for every operation, because the product must be fully usable without a mouse (§13).
R17. Any Phase-0 deviation touched by a page MUST be named there with its removal condition, pointing at CLAUDE.md Article 8.

## Absolute Prohibitions

P1. NEVER hand-maintain a command list, parameter table or AI tool schema in `/docs`; generate it or link the generated file (§2.3, CLAUDE.md 5.10).
P2. NEVER edit `docs/komutlar/referans.md` by hand.
P3. NEVER document a command name, parameter name, default or error text that differs from the source. The source is the truth; the page follows it.
P4. NEVER ship a feature, command, script API, sandbox level, file format or CLI flag without its page.
P5. NEVER write marketing copy, roadmap prose or architectural justification into the user manual — that belongs in `kentoscad.md` and `.claude/`. The manual tells a user how to do their work.
P6. NEVER describe an unimplemented behaviour in the present tense (see R13).
P7. NEVER leave a `TODO`, `TBD`, `XXX`, `Lorem` or an empty section heading in a merged page.
P8. NEVER state a regulatory rule without its madde reference and date (R12).
P9. NEVER use English UI labels in Turkish user documentation; quote the label exactly as the application shows it.
P10. NEVER let a page link to a file that does not exist, inside or outside `/docs`.

## Definitions of Done

- [ ] Every new or changed user-facing behaviour has its page, and the page is linked from `docs/README.md`.
- [ ] A new command has `docs/komutlar/<slug>.md` with all eight required sections and all three invocation paths.
- [ ] `make reference` has been run and `docs/komutlar/referans.md` is committed with the registry change.
- [ ] Every example was executed and produced what the page says it produces.
- [ ] Fenced blocks carry the right tag per R10a; `kentos_tests` is green.
- [ ] Every new domain term is in `docs/sozluk.md`.
- [ ] No `TODO`/`TBD` and no dead link remains.

## Enforcement

- `scripts/ci-gate-docs.sh` — fails when: a registry command has no page; a command page is missing one of the eight sections; `referans.md` differs from a fresh `kentos_docgen` run; a page under `/docs` is not linked from `docs/README.md`; a relative link points at a missing file; a merged page contains `TODO`/`TBD`/`XXX`/`Lorem`; a page has no level-1 heading.
- `tests/unit/test_docs.cpp` — extracts every fenced block from `/docs` and runs it. A
  documented command line that fails, a JSON block that does not parse, or a documented
  script that errors breaks the build. There is no second copy of any example.
- `make docs` — regenerates the reference and runs the gate.
- `make check` — includes the gate, so an undocumented command cannot merge.
